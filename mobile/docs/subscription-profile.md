# Профиль хоста в подписке Proxy Dom

Это пособие для тех, кто продаёт или раздаёт ключи: панелей, хостеров и
владельцев ботов. Оно описывает, как положить карточку профиля в тот же
HTTPS-ответ, из которого клиент уже берёт список узлов.

Клиент не требует нового API, второго запроса или логотипа. Всё едет в одном
ответе подписки.

## Что видит пользователь

- имя профиля и короткое описание;
- название тарифа (`100 GB`, `1 TB`, `Unlimited`);
- остаток трафика крупной цифрой;
- полоску остатка;
- ссылку поддержки;
- дату обновления.

Старые клиенты (Happ, Hiddify, v2rayNG, предыдущие Proxy Dom) продолжают
читать `Profile-Title`, `announce`, `support-url` и
`subscription-userinfo`. Новый клиент сначала читает `proxydom-profile`, а
старые поля использует как fallback.

## Транспорт

Один заголовок:

```http
proxydom-profile: <base64url(UTF-8 JSON)>
```

Если хостинг не умеет ставить свои заголовки, положите ту же строку в тело
подписки:

```text
#proxydom-profile: <base64url(UTF-8 JSON)>
```

Правила:

- заголовок важнее строки в теле;
- если заголовок **есть**, но битый, строка в теле не используется;
- если заголовка нет, используется первая подходящая строка
  `#proxydom-profile:`;
- `base64:`-префикс не нужен;
- переводы строк и пробелы внутри значения не допускаются;
- JSON — не больше 2048 байт, значение заголовка — не больше 2732 символов;
- глубина JSON — не больше 4, неизвестных ключей — не больше 16.

Старые поля не удаляйте. Они нужны другим клиентам:

```http
subscription-userinfo: upload=0; download=27000000000; total=100000000000
profile-title: base64:0KLQtdGA0LXQvA==
announce: base64:0J_QvtC00LTQtdGA0LbQutCwINCyIFRlbGVncmFt
support-url: https://t.me/example_support
profile-update-interval: 12
Cache-Control: private, no-cache
```

## JSON

```json
{
  "version": 1,
  "displayName": "Терем",
  "description": "Поддержка в Telegram",
  "supportUrl": "https://t.me/example_support",
  "supportLabel": "Поддержка",
  "planName": "100 GB",
  "accent": "#8A6A2F",
  "traffic": {
    "upload": 0,
    "download": 27000000000,
    "total": 100000000000,
    "unlimited": false,
    "updatedAt": "2026-10-29T09:00:00Z"
  }
}
```

Все объёмы — **байты**. Не пишите `100` вместо `100000000000`.

Манифест использует десятичные единицы: `1000^3` — ГБ, `1000^4` — ТБ.
Старый `subscription-userinfo` без манифеста клиент показывает в бинарных
единицах (`1024^3`), потому что так его отдают большинство панелей. Поэтому
`total=107374182400` в старом заголовке — это `100 ГБ` на экране, а не `107`.
Если хотите гарантировать десятичные `100 ГБ` и `1 ТБ`, присылайте манифест.

| Поле | Обязательное | Правило |
|---|---|---|
| `version` | да | целое ≥ 1; неизвестные будущие ключи игнорируются |
| `displayName` | нет | до 40 Unicode-символов; пустое — fallback на `Profile-Title` |
| `description` | нет | до 200 символов, максимум 2 строки |
| `supportUrl` | нет | только `https://`, без `user:pass@`, до 200 символов |
| `supportLabel` | нет | до 24 символов |
| `planName` | нет | до 24 символов, показывается под именем |
| `accent` | нет | `#RRGGBB`; сейчас сохраняется, но палитра его не применяет |
| `traffic.upload` | нет | целое 0…10^18 |
| `traffic.download` | нет | целое 0…10^18 |
| `traffic.total` | нет | целое 0…10^18; `0` не значит «безлимит» |
| `traffic.unlimited` | нет | `true` — единственный способ сказать «без лимита» в манифесте |
| `traffic.resetAt` | нет | ISO-8601 с `Z` или смещением; пока не рисуется |
| `traffic.expiresAt` | нет | то же; пока не рисуется |
| `traffic.fairUseNote` | нет | до 120 символов; зарезервировано |
| `traffic.updatedAt` | нет | когда хостер посчитал числа; используется для «устарело» |

`total` — необязательный. Если его нет и `unlimited` нет, клиент покажет
«нет данных о лимите» без полоски. Это не безлимит и не ноль.

### Состояния трафика

| Данные | Что покажет клиент |
|---|---|
| нет ни манифеста, ни старого `subscription-userinfo` | `—`, «нет данных о трафике» |
| `unlimited: true` | `∞`, «без лимита», без полоски |
| только `download`/`upload` | «нет данных о лимите», без полоски |
| `total > 0`, расход меньше | остаток крупно и полоска остатка |
| `total > 0`, расход ≥ total | `0`, пустая полоска, «Трафик закончился» |
| `updatedAt` старше порога | те же числа + «устарело» |

Порог устаревания: `2 × profile-update-interval`; если поля нет — 48 часов;
не меньше 12 и не больше 168 часов.

### Цвет

Полоска показывает **остаток**, а не расход:

- осталось больше 20% — золото;
- осталось от 0 до 20% — пламя;
- осталось 0 — опасный цвет и «Трафик закончился».

Цвет не единственный сигнал: рядом крупный остаток и текст состояния.

## Примеры

### 100 GB, израсходовано 27 GB

```json
{
  "version": 1,
  "displayName": "Терем",
  "planName": "100 GB",
  "traffic": {
    "upload": 0,
    "download": 27000000000,
    "total": 100000000000,
    "updatedAt": "2026-10-29T09:00:00Z"
  }
}
```

Остаток — `73 ГБ`, полоска заполнена на 73% (остаток).

### 1 TB, израсходовано 27 GB

```json
{
  "version": 1,
  "displayName": "Терем",
  "planName": "1 TB",
  "traffic": {
    "upload": 0,
    "download": 27000000000,
    "total": 1000000000000,
    "updatedAt": "2026-10-29T09:00:00Z"
  }
}
```

`1 TB` — это `1000000000000` байт (10^12), а не `2^40`. Остаток — `973 ГБ`,
полоска почти полная: она показывает остаток, а не расход.

### Безлимит

```json
{
  "version": 1,
  "displayName": "Терем",
  "planName": "Unlimited",
  "traffic": {
    "unlimited": true,
    "download": 123456789,
    "updatedAt": "2026-10-29T09:00:00Z"
  }
}
```

Полоски и процента нет. `total` здесь не нужен.

### Без данных

Не отправляйте `traffic` вообще. Не отправляйте `total: 0` вместо
«безлимита»: в манифесте это не безлимит.

### Исчерпан

```json
{
  "version": 1,
  "displayName": "Терем",
  "planName": "100 GB",
  "traffic": {
    "upload": 0,
    "download": 100000000000,
    "total": 100000000000,
    "updatedAt": "2026-10-29T09:00:00Z"
  }
}
```

## Кодирование

`profile.json` должен быть UTF-8 **без BOM**. Не добавляйте перевод строки в
конец перед кодированием, если не хотите, чтобы он попал в JSON.

```bash
python -c "import base64,pathlib; print(base64.urlsafe_b64encode(pathlib.Path('profile.json').read_bytes().strip()).decode().rstrip('='))"
```

Проверить обратно:

```bash
python -c "import sys,base64; s=sys.argv[1].strip(); print(base64.urlsafe_b64decode(s+'='*((4-len(s)%4)%4)).decode())" "ВСТАВЬТЕ_ЗНАЧЕНИЕ"
```

Не используйте обычный `base64` с `+`, `/`, `=` в заголовке, если можете:
клиент принимает его, но URL-safe вариант безопаснее для прокси и логов.

## Проверка

`curl -I` делает HEAD; некоторые панели на HEAD не отдают заголовки. Проверяйте
GET и сохраняйте заголовки:

```bash
curl -sD - -o /dev/null -H "User-Agent: ProxyDom/1.0" \
  "https://example.com/sub/TOKEN"
```

В ответе должна быть одна строка `proxydom-profile:` без переносов. Затем
декодируйте значение и проверьте:

- `version` — целое ≥ 1;
- `traffic.total` в байтах;
- `traffic.download + traffic.upload` не больше `total`;
- `updatedAt` со смещением;
- в JSON нет паролей узлов, UUID и `hy2://` строк.

## nginx

Заголовок должен ставить тот server, который отдаёт подписку:

```nginx
location /sub/ {
    default_type text/plain;
    charset utf-8;

    add_header proxydom-profile "ВСТАВЬТЕ_ЗНАЧЕНИЕ" always;
    add_header subscription-userinfo "upload=0; download=27000000000; total=100000000000" always;
    add_header Cache-Control "private, no-cache" always;
}
```

Это статический пример для одного пользователя. Для персональной квоты
заголовок должен собирать тот слой, который знает токен: панель, njs/lua или
приложение. Не ставьте один `total` на всех.

`add_header` в `location` заменяет унаследованные `add_header` этого блока.
Если upstream уже отдаёт заголовок, nginx пропустит его, пока блок заголовков
влезает в `proxy_buffer_size`. При `upstream sent too big header` уменьшайте
JSON, а не увеличивайте буферы без нужды.

## Caddy

```caddyfile
header /sub/* proxydom-profile "ВСТАВЬТЕ_ЗНАЧЕНИЕ"
header /sub/* Cache-Control "private, no-cache"
```

Для персональной квоты статический `header` не подходит — его должен ставить
аппликационный слой, знающий пользователя.

## Cloudflare Worker

Worker нужен только если origin не может поставить заголовок. Ходите в
отдельный origin-хост, а не в тот же URL, иначе можно снова попасть в Worker:

```js
const ORIGIN = "origin.example.com";

export default {
  async fetch(request) {
    const url = new URL(request.url);
    url.hostname = ORIGIN;
    const response = await fetch(new Request(url, request));
    const headers = new Headers(response.headers);
    headers.set("proxydom-profile", "ВСТАВЬТЕ_ЗНАЧЕНИЕ_ЭТОГО_ЧЕЛОВЕКА");
    headers.set("Cache-Control", "private, no-cache");
    return new Response(response.body, { status: response.status, headers });
  },
};
```

Не включайте `Cache Everything` на этом маршруте. Значение в примере
статическое нарочно; в бою его собирают из квоты токена.

## Статический файл

Один файл — один человек. Общий файл с чужими байтами покажет всем одну и ту
же квоту.

```text
# Мой профиль
#proxydom-profile: ВСТАВЬТЕ_ЗНАЧЕНИЕ
#subscription-userinfo: upload=0; download=27000000000; total=100000000000
#support-url: https://t.me/example_support
hysteria2://user:pass@203.0.113.10:443/?sni=a.example#One
```

Человеческое имя ставьте **до** служебных строк: старые клиенты берут первую
строку `#…` как имя. Новый клиент пропускает `#proxydom-profile`,
`#subscription-userinfo`, `#announce` и `#support-url` при выборе fallback-имени
и умеет читать `#profile-title:`.

## Кэш и чужая квота

- персональный ответ: `Cache-Control: private, no-cache`;
- `ETag` должен меняться, когда меняются `upload`, `download`, `total` или
  `updatedAt`; иначе клиент получит `304` и оставит старые числа;
- не отдавайте ответ с `Cache-Control: public` на URL, который различается
  только токеном или `x-hwid`;
- если один URL меняется по заголовку запроса, нужен `Vary`;
- токен подписки — секрет; не кладите его в публичный кэш.

Клиент отдельно хранит `trafficUpdatedAt` и не двигает дату квоты на `304`
или пустом `subscription-userinfo`.

## Совместимость

| Клиент | Что прочитает |
|---|---|
| Proxy Dom с манифестом | `proxydom-profile`, иначе старые поля |
| Proxy Dom без манифеста | старые поля; неизвестный заголовок и `#proxydom-profile:` игнорирует |
| Happ, Hiddify, V2Box, Prizrak-Box | свои старые поля; новый заголовок не мешает |
| Mihomo | `subscription-userinfo` у proxy-provider |
| v2rayNG | userinfo, title, support, web page; announce и манифест не читает |

## Частые ошибки

| Симптом | Причина |
|---|---|
| карточки нет | битый base64/JSON, BOM, пробел или перевод строки в заголовке |
| имя стало длинной base64-строкой | манифест стоял первой строкой тела у старого клиента; поставьте человеческое имя первым или используйте `displayName` |
| видно 931 ГБ вместо 1 ТБ | старый `subscription-userinfo` без манифеста; числа в манифесте должны быть в байтах |
| у всех одна квота | общий кэш или статический файл на всех |
| квота не обновляется | `ETag` не меняется; `304` не приносит новых чисел |
| полоска почти полная на 1 ТБ | это остаток 973 ГБ; шкала линейная, смотрите крупную цифру |
| «без лимита» пропало | в манифесте нет `unlimited: true`; `total: 0` — не безлимит |

## Что пока не входит

- подпись манифеста;
- логотип с чужого URL;
- второй запрос за профилем;
- произвольный HTML/Markdown/JS;
- применение `accent` к палитре;
- показ `resetAt`/`expiresAt` и `fairUseNote`.

Эти поля можно присылать, но текущая версия их либо только сохраняет, либо
игнорирует. Не обещайте пользователю то, чего экран ещё не рисует.
