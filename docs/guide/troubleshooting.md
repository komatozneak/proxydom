# Разбор проблем

> Страница для тех, у кого не подключается. Порядок такой: сначала **своя**
> сторона (приложение, ссылка), потом сервер, потом сеть.

---

## 0. Сначала приложите журнал

Почти каждый разбор начинается с одного и того же: «у меня не работает», а
через десять минут выясняется, что в ссылке опечатка в одном символе.
Журнал отвечает на вопрос за секунды.

**Настройки → Журнал → Поделиться.** Отчёт уходит текстом туда, куда вы
выберете — в мессенджер, в заметки, на почту.

Что внутри и что с этим делать:

| Раздел отчёта | Что означает | Первое, на что смотреть |
|---|---|---|
| `vpn_ui` | что видит интерфейс | `error:` и код после него |
| `vpn_native` | состояние нативного слоя | `disconnected` при подключённом туннеле = сбой в слое |
| `vpn_native_last_error` | последняя ошибка движка | часто уже содержит причину |
| `last_vpn_error` | ошибка уровня приложения | код `timeout`, `revoked`, `conflict`, `client_refused` |
| `external_ip` | виден ли туннель снаружи | см. раздел 3 ниже |
| `vpn_stderr_tail` | stderr ядра | последняя ошибка движка |
| `recent_log` | хронология попытки | ищите по `sid` — это номер попытки |

**Безопасность.** Из отчёта вырезаны пароли, токены и адреса узлов — вместо
них `***` и `45.91.***.***`. Ссылка `hysteria2://` в отчёте не появляется
целиком. Но имена ваших серверов и точный текст ошибок — остаются, так что
не отправляйте отчёт в места, где не хотите его видеть.

## 1. Шаблон строки

Чтобы читать журнал, нужна одна картинка:

```
2026-10-05T09:14:22.481Z [warn] [vpn] vpn.connect_fail sid=8f3c-2 code=timeout
└─────────── когда (UTC) ────┘ └ур.┘ └ист.┘ └── событие ──┘ └──── поля ────┘
```

- **время в UTC**, миллисекунды;
- **уровень**: `debug` / `info` / `warn` / `error`;
- **источник** в квадратных скобках — по нему фильтрует экран журнала:
  `vpn` (туннель), `net` (сеть), `hy2` (ядро Hysteria2), `core` (ядро VLESS), `doc`
  (загрузка документа), `ui` (действия);
- **имя события** — стабильное, по нему ищут;
- **поля** — `ключ=значение`.

`sid` — номер попытки подключения. Он общий для приложения и для нативного
слоя, поэтому по нему собирается вся история одной попытки, а не два разных
лога рядом. Если в подписи к ошибке вы видите `sid` — приложите его в
переписке: по нему находится конкретная строка.

Полный контракт журнала — в исходниках:
[`mobile/lib/core/diagnostics/`](../../mobile/lib/core/diagnostics/).

## 2. Не подключается

### Начните с уровня «Ошибки»

Если в журнале сейчас «Информация» или «Отладка» — переключитесь на
«Ошибки». Ошибок станет мало, и они перестанут тонуть.

### Что означают коды

| `code` | Что произошло | Что делать |
|---|---|---|
| `timeout` | сервер не ответил вовремя | проверить, что порт UDP открыт; попробовать `obfs=salamander` |
| `revoked` | систему отозвали | нажать «Подключиться» заново |
| `conflict` | другое VPN-приложение заняло туннель | выключить другое приложение или VPN в настройках системы |
| `client_refused` | адрес сервера из ссылки отклонил приложение | проверить адрес; частая причина — `127.0.0.1` или локальное имя |
| `share_unsupported` | выбранная строка на этом устройстве не запускается | Hysteria2 запускается везде; VLESS — там, где движок его набирает (сейчас Android и Windows, без Reality и XHTTP). Trojan, Shadowsocks и VMess не поддерживаются |
| `gen_have` / `stale` | попытка устарела, пока шла предыдущая | обычно безобидно; если повторяется — смотрите `recent_log` |

### Ссылка не распознаётся при вставке

- Проверьте схему: `hysteria2://` или `hy2://`. С пробелами, кавычками и
  переносами строк внутри — нет.
- Проверьте, что между частями ровно один `?` и что параметры разделены `&`.
- **Если ссылка пришла в мессенджере** — перекопируйте её через QR-код.
  Многие мессенджеры и некоторые терминалы обрезают строку после `&`, и
  получается ссылка без параметров, которая выглядит почти правильной.

### Подключается и сразу отключается

Смотрите в `recent_log` строки с `hy2.socks` или `core.vless` — по ним видно,
дошёл ли разговор до ядра. Если ядро стартует и сразу падает, причина в
ссылке: чаще всего не совпадает `obfs-password` или пароль пользователя.

## 3. Подключается, но трафик идёт мимо

Откройте [icanhazip.com](https://icanhazip.com) и сравните IP с адресом
вашего сервера.

| Что видите | Что это значит |
|---|---|
| IP сервера | всё работает |
| IP домашней сети | туннель не поднят либо трафик идёт в обход |
| IP сервера, но сайты грузятся медленно | до сервера доходит, оттуда — плохо; смотрите `net.path` в журнале |
| `external_ip` в отчёте пустой | проверка выхода не прошла; ищите `vpn.egress_probe` |

Если часть приложений работает через туннель, а часть — нет, проверьте
раздел настроек приложений (только на Android).

## 4. Свой сервер {#сервер}

### Порт не слушается

```bash
sudo systemctl status hysteria-server
sudo ss -lunp | grep 443
```

Если порта нет — служба не запустилась после правки конфига:

```bash
sudo systemctl restart hysteria-server
sudo journalctl -u hysteria-server -b --no-pager | tail -30
```

Ошибка `no such host` при выпуске сертификата — DNS-запись ещё не разошлась
или указывает не на этот сервер:

```bash
dig +short sub.вашдомен.ru
```

### Подключения не приходят вовсе

Проверяйте **три места** — обычно дело в одном из них, и не в том, где вы
смотрите первой:

1. **Панель файрвола хостинга.** Security Group / Firewall / «Правила
   файрвола». 443/UDP должен быть открыт.
2. **Файлвол в системе.** `sudo ufw status` — если `ufw` активен, порт надо
   открыть и здесь.
3. **Сервис.** `sudo systemctl status hysteria-server`.

Пока вы смотрите `journalctl`, а закрыт порт в панели хостинга, в журнале
будет пусто — и это выглядит как «сервер молчит».

### Сертификат не выпускается

```bash
sudo journalctl -u hysteria-server -b | grep -i acme
```

Типичные причины: закрыт 80/TCP, домен не резолвится в IP этого сервера,
почта в `acme.email` указана неверно. Let's Encrypt не выпустит сертификат на
домен, который не указывает на этот сервер.

### `authentication failed`

Пароль в ссылке не совпадает с блоком `userpass` в конфиге. Проверьте
регистр и раскладку клавиатуры. Напоминание формата:

```
hysteria2://ЛОГИН:ПАРОЛЬ@АДРЕС#Имя
```

`ЛОГИН:`, `ПАРОЛЬ`, `АДРЕС`, `#Имя` — разделяются без пробелов.

## 5. Windows

Windows-версия пишет журнал службы отдельно от окна приложения. При отправке
отчёта они собираются вместе, но вручную файлы лежат так:

| Файл | Что внутри |
|---|---|
| `%ProgramData%\Proxy Dom\logs\service.log` | журнал службы (ротация: + `service.log.1`) |
| `%USERPROFILE%\Downloads\proxydom-debug.txt` | выгрузка из окна приложения |

Если окно приложения и служба расходятся во мнении о состоянии — смотрите
обе части. В отчёте они под заголовками `=== window ===` и `=== service ===`.

**На VLESS-строке счётчики трафика пустые — это ожидаемо.** Ядро VLESS не
отдаёт API со счётчиками (у Hysteria2 он есть), поэтому цифрам неоткуда взяться:
в журнале вместо строк `flow_rate` и `flow_total` будет одна
`flow api_unreachable`. Соединение при этом работает. Судите по внешнему
адресу, как в разделе 3, а не по счётчикам: пустые цифры на VLESS — не признак
поломки.

## 6. Подключение рвётся само по себе

Обычная причина — смена сети: переход между Wi-Fi и мобильными данными,
спящий режим, смена IP у провайдера. Приложение это переживает и
переподключается само; в журнале видно по `sid` — появляется новая попытка.

Если переподключение не помогает и повторяется каждые несколько секунд:

- проверьте, не включена ли в системе блокировка VPN («Always-on» /
  «Блокировка подключений без VPN»). Код `conflict` в журнале;
- перезапустите приложение: иногда после долгого простоя остаётся
  «зависшее» состояние туннеля;
- на Windows — проверьте, что служба запущена
  (`services.msc` → «Прокси Дом»).

## 7. Чего в приложении нет

Чтобы не искать:

- **kill switch** внутри приложения нет. Что делать при обрыве, решает
  система или настройка «Блокировка подключений без VPN».
- **выбора приложений на iOS** нет — система такого не позволяет.
- **автоподбора сервера** нет: подключается тот, который вы нажали.
- **Trojan, Shadowsocks и VMess не поддерживаются.** VLESS допущен в импорт
  там, где движок его набирает (сейчас Android и Windows; Reality и XHTTP —
  нет, и на iOS движка VLESS нет).
  Строки, которые это устройство не запускает, показываются серым и не
  подключаются. Документ при этом не удаляется.
- **«Что работает без VPN» на VLESS не действует.** Список сайтов, которые
  должны идти мимо туннеля, применяется только на Hysteria2. На VLESS-строке
  весь трафик идёт через сервер, кроме локальной сети. Это касается и
  Android, и Windows. В журнале Windows такая сессия пишет
  `routing_applied=false dns_hijack=false` — применять действительно нечего,
  и раньше там стояло `true` по ошибке.
- **обновления портов (`mport`)** на Android и iOS нет. Эти параметры
  понимает только Windows-версия.

## 8. Как отправить отчёт по делу

Один абзац экономит переписку:

1. что ожидалось и что получилось;
2. устройство и версия приложения (они есть в отчёте автоматически);
3. время, когда это происходило (в отчёте — UTC, приведите к своему);
4. `sid` из строки ошибки, если он есть;
5. сам отчёт.

И не надо прикладывать скриншоты экрана с ключами от других серверов —
достаточно журнала: в нём секретов нет, а информативность выше.
