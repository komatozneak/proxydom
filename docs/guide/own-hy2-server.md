# Как поднять свой сервер Hysteria2

> Полное руководство от пустого сервера до работающей ссылки, которую можно
> вставить в приложение. Рассчитано на Ubuntu 22.04 / 24.04.
> Время: 20–40 минут, в основном ожидание выпуска сертификата.

---

## 0. Что понадобится

| Что | Зачем | Где взять |
|---|---|---|
| VPS с Ubuntu 22.04+ | сам сервер | любой VPS-провайдер, самый дешёвый тариф |
| Домен или поддомен | имя для TLS-сертификата | регистратор доменов |
| `curl` в консоли | установка | уже есть в Ubuntu |

**Проверьте главное заранее.** Hysteria2 работает по **UDP**. Перед покупкой
сервера уточните у хостинга, что UDP-порты вам выдают. Если в тарифе стоит
«трафик 5 ТБ» и при этом UDP закрыт — деньги потрачены впустую.

---

## 1. Откройте порты

Серверу нужны два порта:

- **443/UDP** — сам Hysteria2;
- **80/TCP** — только если будете выпускать сертификат через ACME
  (способ 2а в разделе 4). Если способ 2б — не нужен.

В консоли сервера:

```bash
sudo ufw allow 443/udp
sudo ufw allow 80/tcp
sudo ufw status
```

Если у хостинга есть отдельная панель файрвола (панель VPS, Security Group в
AWS, Firewall в Selectel) — порт надо открыть **и там тоже**. Это самая
частая причина «всё настроил, а не подключается».

---

## 2. Подготовьте домен

DNS-запись типа **A** должна указывать на IP вашего сервера.

```bash
dig +short sub.вашдомен.ru
```

Команда должна вернуть IP вашего сервера. Если вернула пусто — подождите
несколько минут, DNS расходится медленно. Проверять имеет смысл, когда
команда уже возвращает нужный IP, но подключиться всё равно не идёт:
значит, дело в чём-то другом.

> Нет домена? Можно пропустить раздел 4 и использовать способ 2б
> (самоподписанный сертификат) — приложение его примет, если в ссылке стоит
> `insecure=1`.

---

## 3. Установите Hysteria2

Официальный установщик сам скачает нужную версию, создаст пользователя
сервиса и systemd-юнит:

```bash
bash <(curl -fsSL https://get.hy2.sh/)
```

Проверьте, что служба жива:

```bash
systemctl status hysteria-server
```

Должно быть `active (running)`. Если `inactive (dead)` — переходите к
разделу 4, без конфига служба и не запустится.

---

## 4. Настройте конфиг

```bash
sudo nano /etc/hysteria/config.yaml
```

### Способ 2а. С доменом и нормальным сертификатом (рекомендуется)

```yaml
# /etc/hysteria/config.yaml
acme:
  domains:
    - sub.вашдомен.ru
  email: вы@вашдомен.ru
  ca: letsencrypt

listen: :443

auth:
  type: userpass
  userpass:
    мойлогин: мойпароль

# Маскировка под обычный сайт: кто-то всё же решит открыть ваш домен.
masquerade:
  type: proxy
  proxy:
    url: https://example.com/
    rewriteHost: true

# Необязательно, но полезно: без этого любой может узнать, что на вашем
# IP что-то открыто, просто дождавшись рукопожатия.
obfs:
  type: salamander
  salamander:
    password: ещё_один_длинный_пароль
```

Перезапуск:

```bash
sudo systemctl restart hysteria-server
sudo systemctl status hysteria-server
```

### Способ 2б. Без домена, самоподписанный сертификат

```yaml
# /etc/hysteria/config.yaml
listen: :443

tls:
  cert: /etc/hysteria/self.crt
  key: /etc/hysteria/self.key

auth:
  type: userpass
  userpass:
    мойлогин: мойпароль
```

Сертификат выпускается один раз:

```bash
cd /etc/hysteria
sudo openssl req -x509 -nodes -newkey rsa:2048 \
  -keyout self.key -out self.crt -days 3650 -subj "/CN=hysteria.local"

sudo chmod 600 self.key
sudo systemctl restart hysteria-server
```

**Такой способ работает**, но в ссылке обязан быть `insecure=1` (раздел 6).
Приложение не сможет проверить сертификат — и честно предупредит об этом.

---

## 5. Придумайте пароли

Два независимых пароля:

- **пароль пользователя** — вход на сервер. Это то, что стоит в ссылке.
- **пароль обфускации** (`obfs-password`) — дополнительный слой.

Требования к обоим:

- длиннее 12 символов;
- **без** `@`, `:`, `/`, `?`, `#`, `&`, `%` и пробелов — это символы, которые
  имеют значение в ссылке, и их придётся экранировать, а ошибка в этом месте
  выглядит как «сервер не отвечает» вместо «неверная ссылка».

Сгенерировать надёжный пароль:

```bash
openssl rand -base64 18 | tr -d '/+='
```

## 6. Соберите ссылку

Формат:

```
hysteria2://ПАРОЛЬ:ДОП_ПАРОЛЬ@АДРЕС:ПОРТ?ПАРАМЕТРЫ#Имя
```

Разберём по частям (значения — пример для способа 2а с доменом):

```
hysteria2://мойпароль:ещё_один_длинный_пароль@sub.вашдомен.ru:443
  ?sni=sub.вашдомен.ru
  &insecure=0
  &obfs=salamander
  &obfs-password=ещё_один_длинный_пароль
#Мой сервер
```

Собранная одной строкой:

```
hysteria2://мойпароль:ещё_один_длинный_пароль@sub.вашдомен.ru:443?sni=sub.вашдомен.ru&insecure=0&obfs=salamander&obfs-password=ещё_один_длинный_пароль#Мой сервер
```

### Что понимает приложение

| Часть | Что делает | По умолчанию |
|---|---|---|
| `hysteria2://` или `hy2://` | схема | — |
| до `@` | логин и пароль. Можно `пароль` или `логин:пароль` | — |
| после `@` | адрес и порт | порт `443` |
| `sni=` | имя для TLS | берётся из адреса |
| `insecure=1` | не проверять сертификат. **Только для способа 2б** | выключен |
| `obfs=salamander` | режим маскировки | выключен |
| `obfs-password=` | пароль обфускации | нет |
| `#Имя` | подпись в списке серверов | берётся из адреса |

### Чего приложение не понимает

**`mport` и `mportHopInt` (перебор портов) — не поддерживаются на Android и
iOS.** Эти параметры понимает только Windows-версия. Если вы вставите такую
ссылку в мобильное приложение, лишние параметры будут молча проигнорированы:
сервер на переборе портов работать не будет, и причина будет неочевидна.
Пользуйтесь одним портом — этого достаточно для личного использования.

### Проверка ссылки

Скопируйте ссылку целиком (включая `#Имя` — это не комментарий, часть ссылки)
и вставьте в приложение. Если в поле ввода не узнаётся ссылка — чаще всего
виноват `&` в начале строки: некоторые терминалы и мессенджеры съедают
остаток строки после `&`. В таком случае вставляйте ссылку через QR-код
(раздел «Использование» в [using-the-client.md](using-the-client.md)).

## 7. Проверьте, что сервер отвечает

Не дожидаясь приложения:

```bash
sudo ss -lunp | grep 443
```

Порт должен быть в списке. Если его нет — смотрите
[разбор проблем](troubleshooting.md#сервер).

Быстрая проверка, что процесс видит попытки подключения:

```bash
sudo journalctl -u hysteria-server -f
```

При подключении приложения здесь появятся строки соединения. Если они есть, а
в приложении «Не подключено» — дело в приложении или в ссылке, а не в сервере.

---

## 8. Обслуживание

| Задача | Команда |
|---|---|
| Статус | `systemctl status hysteria-server` |
| Перезапуск после правки конфига | `sudo systemctl restart hysteria-server` |
| Журнал сервера | `sudo journalctl -u hysteria-server --since "1 hour ago"` |
| Журнал с момента загрузки | `sudo journalctl -u hysteria-server -b` |
| Версия | `hysteria version` |

**Добавление пользователя.** Просто допишите строчку в `userpass` и
перезапустите. Старые пользоваенты продолжают работать.

**Смена пароля.** То же самое. Старая ссылка перестаёт работать — это и
правильно, если пароль утек.

**Резервные копии.** Копируйте `/etc/hysteria/config.yaml`: в нём и пароли,
и адреса. Храните в менеджере паролей, не в репозитории и не в облаке без
шифрования.

---

## 9. Частые ошибки

| Симптом | Причина | Что делать |
|---|---|---|
| Порт 443 не слушается | не перезапустили службу после правки | `sudo systemctl restart hysteria-server`, затем `journalctl` |
| `no such host` в приложении | DNS-запись ещё не разошлась | `dig +short sub.вашдомен.ru`, подождать |
| Таймаут подключения | закрыт UDP-порт в панели хостинга | открыть 443/UDP в панели **и** в `ufw` |
| Сертификат не выпустился | 80/TCP закрыт, или домен не резолвится | `sudo journalctl -u hysteria-server -b \| grep -i acme` |
| Подключается и сразу отваливается | не совпал `obfs-password` | сверьте его с конфигом; пробелы в значении ломают пароль |
| `authentication failed` | не совпал пароль пользователя | проверьте блок `userpass`; в ссылке логин и пароль разделены `:` |
| Приложение не узнаёт ссылку | `&` съеден при копировании | вставляйте через QR-код |
| Работает на ПК, не работает на телефоне | телефон в сети, где режется UDP | попробуйте включить `obfs=salamander` |
| Работает без обфускации, не работает с ним | опечатка в пароле обфускации | временно уберите `obfs` из ссылки и проверьте |
